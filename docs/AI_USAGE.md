## 2026-11-08：机会判别接口试运行

模型服务使用现有 Codex 配置中的 `gpt-6.1-sol`，通过 Codex 当前 Responses API 服务及本机凭据调用。密钥没有写入项目文件。具体地址、成本单价和转发服务计费规则没有写入报告；费用因此标为未知。

用途是测试机会判别结构、四项条件、官方分类标签和逐字证据检查。模型看到 7 条公开文本作为试运行记录：先 2 条 GitHub 项目，再选 GitHub、Hacker News、IT之家、量子位、V2EX 各 1 条。后 5 条请求耗时约 72 秒，服务用量为 4,706 输入 token、1,272 输出 token；2 条请求用量为 1,130 输入 token、1,189 输出 token。结果保存在本地忽略的 `results/` 目录，不作为人工标注或最终验证数据。

生成内容用于判断代码是否能返回四项条件、标签和原文摘句。程序从“存在可观察需求、AI 为核心、技术可实现、无排除项”派生机会标签，并验证摘句确实出现在原文中。试运行记录全部被判为非机会，原因涵盖产品说明缺少明确需求、AI 并非核心、新闻转述及宣传内容。confidence 是模型自评，尚未校准。

全量运行过程中服务返回 `items`、`results`、`records` 等不同结果列表键名，证据摘录也可能改变标点。解析器统一了列表结构，并把标点差异引句转换为原文连续片段。较大批次出现一次 HTTP 读取超时，读取超时因而提高到 420 秒，每批最多重试三次。恢复目录为 `results/B01/20261107T173708748922Z/`，已保存 6 个成功检查点。早期失败请求未记录 token 用量，费用未知。

## 2026-11-08：B01 AI 辅助复核

在不修改原人工复核队列的前提下，使用 `scripts/assistant_review.py` 读取 509 条复核记录，生成独立的 AI 辅助复核结果。每批 8 条、最多 3 个并发；正文摘要送入模型，完整正文用于证据回溯。结果经过 record_id、官方功能和行业、正文摘录以及数量一致性审计。

复核模型为本机 Codex 配置中的 `gpt-6.1-sol`，输入 758,777 token，输出 97,710 token，缓存输入 259,677 token，耗时约 2,595 秒。服务单价未配置，费用未知。

509 条中，AI 辅助判断 141 条为机会，与原模型一致 379 条；129 条由原模型机会改为非机会，1 条由原模型非机会改为机会。197 条标记为边界情况，分歧或边界记录共 232 条。这个一致率只能说明模型输出的差异，不能替代真人真值，也不能计算真实 Precision、Recall 或 F1。复核模型看到了原模型字段，结果存在锚定风险。

输出位于 `results/B01/20261107T173708748922Z/review/assistant_review/`，包括结构化结果、CSV、批次检查点和 `human_attention.csv`。原 `review_queue.jsonl` 与 `review_queue.csv` 的 `human_*` 字段保持空白。详细统计见 [B01 AI 辅助复核报告](../reports/REVIEW_ASSISTED_B01.md)。

随后增加盲复核：提示中只保留记录编号、来源、正文类型、标题和正文摘要，去掉原模型判断及第一轮辅助结果。盲复核输出位于 `review/assistant_review_blind/`，509 条中 109 条判为机会，170 条为边界；与第一轮辅助复核有 419 条判断一致。三方对照位于 `review/review_comparison_blind/`，共识表 509 条，三方分歧、边界或分类分歧清单 328 条。两次辅助复核仍使用同一个模型，结果只用于敏感性分析和真人复核排序。

240 条负例按来源网站和正文类型轮转，并在每个分层优先选择模型置信度较低的记录。该定向抽样不能用于无偏估算整个负例池的漏判率或召回率。三方审计脚本会核对共识、边界、分类差异及稳定候选清单。

用户要求用模型承担需要人工复核的工作后，对三方对照清单中的 328 条冲突、边界或分类分歧记录再次调用模型裁定。181 条稳定记录保留盲复核标签，合并形成 509 条 `assistant_review_proxy`。裁定使用原模型、两轮辅助结果和正文证据，仍标记为 `Codex model, not human`。代理机会数量为 100 条，原人工队列没有改写。

代理结果进一步导出为独立的 `assistant_proxy_result2.csv`，其中 509 条使用代理标签，2,052 条未抽样记录保留原模型标签。用代理机会集合重跑得到 14 个候选主题，12 个为单记录主题，轮廓系数 0.204。该结果用于继续开发和论文方法展示，不能替代真人真值或正式比赛结果。

## 2026-11-09：论文整理与交付

依据用户选定的中文、系统方法加 B01 案例、XeTeX/Word 输出路线，对现有 TeX 论文进行证据与表达修订。重点操作包括核对 2,561 条清洗记录、2,872,796/588,074 个全量判别 token、509 条复核队列、100 条代理机会、14 个代理主题及 C2 分数；增加任务映射表、复核一致率表、评分归一化公式和角色权限说明；修正混合代理图的全量分母、LaTeX 百分号转义及 `body` 字段的完整性表述。

引用核对通过 Crossref 检查 6 个 DOI 的题名记录，并以 arXiv API 核实 E5 技术报告编号；GitHub、Hacker News Algolia、WordPress API 和 E5 模型页面均返回可访问响应。未依据外部文献补入研究结果。

论文校订 PDF 经 Tectonic 0.17.0 的 XeTeX 引擎编译两遍，再用 Poppler 渲染逐页检查；Word 由 Pandoc 3.7.0.2 从相同 TeX 正文展开转换，使用项目内 `repair_docx_surface.py` 设定 A4 页面、中文字体与黑色标题，再由 Microsoft Word 365 导出临时 PDF 渲染 9 页复核。TeX PDF 为 11 页，Word 因分页和表图布局为 9 页；正文、数值、表题、引用和六张图保持一致。

第一份 Word 渲染检查发现任务映射表起始数字被转换器吞掉，随后改为带中文前缀的数字并重新导出。独立论文复核另发现 LaTeX 正文百分号未转义，修正后重新编译并复查百分号段落。首次 Tectonic 编译曾将结果写入已有 `paper/manuscript/main.pdf`，该文件现保留为当时产物；后续每次编译均输出至新建的 `C:/Tmp` 目录，交付文件使用日期化新名称。

当前论文结果仍属探索性案例：真人复核字段为空，509 条代理队列之外的 2,052 条标签沿用原模型；正式 result2、result3、result4 和完整策划案没有由本次论文排版操作生成。Tectonic PDF 和 Word 渲染只验证交付文本与版面，不替代上述竞赛研究工作。
