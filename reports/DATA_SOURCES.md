# 数据来源与采集依据

## 范围

首批方向为综合 AI 应用机会，覆盖多个行业。时间窗按北京时间确定，参考日期为 2026-11-07，向前包含 90 个自然日，起点为 2026-08-10 00:00。结束时间取采集启动时间与参考日结束时间的较早值。

采用公开 API 和网站公布的订阅入口。附件 2 的清单是参考资料，题目允许清单之外的公开渠道，也没有要求使用清单内全部网站。数据来源应提供不同类型的信号，避免仅靠科技资讯推断终端需求。

## 本批来源

| 来源 | 获取方式 | 信号用途 | 可用指标与限制 |
| --- | --- | --- | --- |
| GitHub | REST 搜索仓库、Issue，读取热门项目 README | 已有产品能力、工程需求和使用障碍 | 星标、Fork、Issue 讨论与反应；仓库创建日期限制会遗漏较早建立但近期活跃的项目 |
| Hacker News | Algolia 公共搜索 API，覆盖 Ask HN、Show HN、文章和评论 | 用户寻解、产品尝试、使用体验 | 投票和评论数；评论不一定提供独立互动指标，英文技术社区样本有行业偏向 |
| 量子位 | 首页公开的 WordPress REST 接口 | 中文 AI 应用、商业动向、技术内容 | 接口未提供浏览量；不能将文章数量等同于需求人数 |
| IT之家 | 首页公开的 RSS | 中文近期产品与应用资讯 | 仅订阅源当前返回内容，无完整 90 天历史和互动量 |
| V2EX | 首页公开的技术订阅与全站订阅 | 中文用户问题、工具选择和产品分享 | 仅订阅源当前返回内容，不使用需要令牌的 API 2.0 |

项目与 Issue 属于同一个 GitHub 来源，不增加网站覆盖数。Hacker News 的文章、主题和评论同理。多源证据仍应核验是否为同一事件的相互引用。

## 检索

完整检索词和分页上限保存在 `configs/collection.json`，每批保存配置副本。

- GitHub：仓库简介包含 AI、agent 或 RAG，公开非 Fork、非归档项目，星标至少 20；Issue 检索 AI、LLM、AI agent，并设置最少讨论数，按星标或评论数降序。
- Hacker News：分别检索 AI、LLM、automation、agent、RAG，并限定主题类型及发布时间。接口按相关性、投票、评论排序，保留前若干页，避免无界采集。
- 量子位：按发布时间获取时间窗内文章，再用配置中的中英文 AI 相关词筛选。
- RSS：读取公布的订阅源，然后按时间窗和 AI 相关内容筛选。

采集相关词用于决定数据集的主题范围，不生成机会标签。术语不完全覆盖和语义歧义可能造成漏检或误收，应结合人工抽样估计相关性。

## 接口规则

使用前已阅读当前入口及规则，相关页面保存到 `data/reference/web_policies/`。

- [GitHub 搜索说明](https://docs.github.com/en/rest/search/search)：未认证搜索每分钟最多 10 次，每个检索最多返回 1,000 条；脚本在 GitHub 请求间保留至少 7 秒。
- [GitHub 条款 H](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#h-api-terms)：API 使用受条款及隐私政策约束，禁止过量请求和为垃圾信息目的采集。
- [Hacker News 搜索 API](https://hn.algolia.com/api)：公开搜索和日期筛选，单 IP 每小时 10,000 次。脚本使用远低于此值的请求频率。
- [量子位首页](https://www.qbitai.com/) 公布 RSS 和 `wp-json`，其 API 索引明确公开文章 GET 接口。`robots.txt` 限制后台路径，采集使用公开文章接口。
- [IT之家首页](https://www.ithome.com/) 公布 RSS。仅获取 `/rss/`，不使用 robots 禁止的搜索、评论及查询参数页面。
- [V2EX 首页](https://www.v2ex.com/) 公布订阅地址；[API 文档](https://www.v2ex.com/help/api) 的 2.0 接口需要令牌，本批通过公开订阅获取内容。

站点公开访问和 robots 允许访问不等同于授予再分发许可。GitHub 仓库许可证按接口返回值保存，其适用范围仍需结合仓库确认；其他内容没有推定为开放许可。默认只在本地保存研究数据，不上传第三方正文。

## 获取边界

RSS 无法追补历史内容，搜索 API 有结果和分页限制。各来源的请求清单保存可见总数、获取页数、是否截断和实际错误。没有通过的接口不生成假记录，也不伪造时间、热度或正文。

采集清单可重新执行，但网站内容和热度会变化。复现实验应使用保存的批次快照与相同配置，不能使用新采集的数据宣称复现了同一结果。
