## 证据与规则

模型输出四个条件：可观察需求、AI 核心性、技术可实现性和排除项。程序以 0.5 作为机会候选的最低自评阈值，据此计算 `is_opportunity`，并验证机会记录的功能和行业属于官方标签。结果表中的机会置信度按机会方向输出，非机会记录取 `1-confidence`。模型证据必须能回到清洗正文；无法匹配的批次被拒绝并重试。完整性审计检查 2,561 个 record_id、标签、置信度和正文证据，错误数为 0。

## 人工复核

自动结果暂不作为最终研究真值。模型把产品介绍、测试任务、新闻和部分项目说明判为机会的情况已经出现，必须由人工复核确认“真实需求”是否存在。

已生成复核队列：

```powershell
uv run python scripts/build_review_queue.py --run results/B01/20261107T173708748922Z --negative-sample 240
```

审计复核清单：

```powershell
uv run python scripts/audit_review_queue.py --review results/B01/20261107T173708748922Z/review
```

人工填完结果后，可以运行 `scripts/finalize_review.py` 将人工标签覆盖到全量 result2，并计算人工覆盖范围。只有当复核队列全部填完时，才能把全量标签当作最终人工结果并计算 Precision、Recall、F1、混淆矩阵和概率校准指标。

队列位于 `results/B01/20261107T173708748922Z/review/`，共 509 条，包含全部 269 条候选机会及 240 条负例。负例按来源网站和正文类型轮转抽取，同层中优先选择模型置信度较低的记录。人工结果栏保持空白。

全量自动结果和分层人工队列分开保存。没有人工确认前，不进入最终主题聚合和价值排名；可用于开发流程的中间聚类必须标为候选结果。
